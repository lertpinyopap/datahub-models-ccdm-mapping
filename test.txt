That points to non-deterministic source selection, not SCD2 itself.

`CARD_PAYMENT_INSTRUMENT_HISTORICAL_INITIAL_LOAD` deduplicates by:

```sql
partition by AMED_CARD_NBR, SOURCE_EFFECTIVE_FROM_DATETIME
order by SOURCE_SNAPSHOT_DATETIME desc
```

If two candidate rows share the same card, effective date, and `AIRFLOW_DAG_TIME`, Snowflake can choose either row. Also, `ACCOUNT_BASE_SEGMENT` can multiply an Embosser row when an account/org has multiple customer/application contexts.

Check for tied source candidates:

```sql
with candidates as (
  select
    e.amed_card_nbr as payment_instrument_id,
    coalesce(
      cast(e.amed_card_activated_date as timestamp_ntz),
      cast('1900-01-01' as timestamp_ntz)
    ) as valid_from_datetime,
    e.airflow_dag_time as source_snapshot_datetime,
    a.ambs_cust_nbr as customer_id,
    a.ambs_aps_acct as application_number
  from DATAOPS_HUB_SHARE_VISION_NONPROD.RAW.EMBOSSER_RECORD e
  inner join (
    select distinct
      ambs_acct,
      ambs_org,
      ambs_cust_nbr,
      ambs_aps_acct
    from DATAOPS_HUB_SHARE_VISION_NONPROD.RAW.ACCOUNT_BASE_SEGMENT
  ) a
    on e.amed_post_to_acct = a.ambs_acct
   and e.amed_org = a.ambs_org
  where e.amed_card_nbr is not null
    and trim(e.amed_card_nbr) <> ''
)
select
  payment_instrument_id,
  valid_from_datetime,
  source_snapshot_datetime,
  count(*) as candidate_rows,
  count(distinct customer_id || '|' || application_number) as account_contexts
from candidates
group by 1, 2, 3
having count(*) > 1
order by candidate_rows desc, payment_instrument_id, valid_from_datetime;
```

Check whether the account source itself is ambiguous:

```sql
select
  ambs_acct,
  ambs_org,
  count(distinct ambs_cust_nbr || '|' || ambs_aps_acct) as account_contexts
from DATAOPS_HUB_SHARE_VISION_NONPROD.RAW.ACCOUNT_BASE_SEGMENT
group by 1, 2
having count(distinct ambs_cust_nbr || '|' || ambs_aps_acct) > 1
order by account_contexts desc, ambs_acct, ambs_org;
```

If either query returns rows, the spec needs a defined account-snapshot selection rule before joining—not merely another arbitrary tie-breaker. Otherwise different parent/account attributes can be selected each run, changing the business hash and therefore the SCD2 row count.
